# Data model

Single source of truth: `src/db/schema.ts`. Generated SQL lives in `drizzle/`.

## Conventions

- Primary keys are prefixed ULID-ish text ids (`ev_…`, `per_…`, `pr_…`) generated by `src/lib/ids.ts`. Readable in logs and exports, sortable by creation time.
- Every tenant table carries `organization_id` directly, even when it is reachable transitively, so isolation is one predicate away.
- Timestamps are `timestamptz`. `created_at` / `updated_at` on every table.
- Provenance columns on every generated artefact: `data_origin` (`mock` | `live` | `local`), `model_provider`, `model_id`, `prompt_template_version`, `schema_version`, `generated_by_user_id`, `generated_at`, `evidence_cutoff`, `review_status`.
- Enums are Postgres enums so bad values fail at the database, not in TypeScript only.

## Key tables

### `evidence_records`
The centre of the product. Columns beyond the ids: `source_type`, `source_system`, `source_location` (page/offset/timestamp), `observed_at`, `ingested_at`, `speaker`, `raw_text`, `redacted_text`, `normalized_claim`, `category` (15-value enum), `provenance` (`observed` | `externally_supported` | `inferred` | `brand_assertion`), `journey_stage`, `sentiment`, `entities[]`, `vocabulary[]`, `candidate_segment_labels[]`, `pii_status`, `extraction_confidence`, `quality_score`, `created_by_model`, `prompt_template_version`, `review_status`, `char_start`, `char_end`, `availability` (`available` | `source_deleted`).

`source_location` plus `char_start`/`char_end` is what makes "open original source context" work. Deleting a source sets `availability = 'source_deleted'` on derived evidence and deletes embeddings, but never deletes an approved persona version that referenced it — those references render as unavailable and the persona is queued for review.

### `evidence_embeddings`
`evidence_id`, `model_id`, `dimensions`, `embedding vector(1536)`, HNSW index on cosine distance. Separate table so re-embedding with a new model is additive.

### `persona_versions` / `persona_fields` / `persona_field_evidence`
`persona_fields` is one row per claim (a persona has many constraint rows, many decision-criterion rows). Each carries `statement`, `field_type`, `provenance`, `confidence`, `confidence_components` (jsonb — all eight terms), `confidence_explanation`, `evidence_count`, `source_mix` (jsonb), `insufficient_evidence` (bool), `locked` (bool). `persona_field_evidence` is the join carrying `relation` = `supports` | `contradicts`.

That join table is the literal implementation of "every persona claim links to evidence".

### `prompts`
Carries the full spec field list including `generic_control_prompt`, `expected_answer_elements[]`, `constraints_used[]`, `decision_criteria_used[]`, `vocabulary_used[]`, `inclusion_rationale`, `tracking_priority`, `execution_mode`, `normalized_hash`, `profound_metadata` (jsonb), `profound_sync_state`. `prompt_pairs` links a persona prompt to its generic control so the pairing survives editing either side.

### `profound_sync_jobs` + `profound_sync_items`
The receipt. The job row stores counts, request/response hashes, the dry-run response and the final response as jsonb; the item rows store per-prompt outcome (`created` | `duplicate` | `failed` | `skipped`), the Profound prompt id and the error. Retry re-runs only items with outcome `failed`. Both are insert-only after completion.

### `profound_prompt_links`
`(prompt_id, profound_category_id, profound_prompt_id, prompt_set_version, normalized_hash, request_hash)` with a unique constraint on `(organization_id, profound_category_id, normalized_hash)`. This unique index *is* the idempotency guarantee: a second deployment of the same normalized prompt into the same category cannot insert a second link, so it is reported as a duplicate rather than created again.

### `profound_result_snapshots`
Immutable. `(profound_prompt_id, run_id, run_date, model, model_id, region, asset, tags[], visibility_score, share_of_voice, mention_count, executions, average_position, citation_count, citation_share, citations jsonb, mentions jsonb, search_queries jsonb, sentiment_themes jsonb, raw_answer, synced_at, data_origin)`. Unique on `(organization_id, profound_prompt_id, run_id, model_id)` so re-retrieval is idempotent.

### `jobs`
The queue. `type`, `payload jsonb`, `status`, `attempts`, `max_attempts`, `run_after`, `locked_at`, `locked_by`, `last_error`, `result jsonb`, `idempotency_key` (unique when present). Indexed on `(status, run_after)` for the claim query.

### `audit_logs`
`actor_user_id`, `organization_id`, `brand_id`, `action`, `entity_type`, `entity_id`, `metadata jsonb`, `ip`, `created_at`. Written for auth events, approvals, exports, deletions and every Profound write.

## Indexes

- `(organization_id, brand_id, created_at desc)` on every listable brand-scoped table.
- `evidence_records`: GIN on `to_tsvector('english', coalesce(normalized_claim,'') || ' ' || coalesce(redacted_text,''))` for full-text search; btree on `category`, `journey_stage`, `provenance`, `review_status`, `observed_at`; GIN on `entities`, `candidate_segment_labels`.
- `evidence_embeddings`: HNSW `vector_cosine_ops`.
- `prompts`: unique `(prompt_set_version_id, normalized_hash)` to stop duplicates inside one set.
- `profound_prompt_links`: unique `(organization_id, profound_category_id, normalized_hash)`.
- `profound_result_snapshots`: unique `(organization_id, profound_prompt_id, run_id, model_id)`.

## Immutability rules

| Table | Rule |
| --- | --- |
| `persona_versions` | No update once `status = 'approved'` except `review_state` transitions triggered by evidence deletion |
| `prompt_set_versions` | No update once `status = 'approved'` |
| `prompts` | No text/metadata update once its set version is approved |
| `profound_sync_jobs`, `profound_sync_items` | Insert-only after terminal status |
| `profound_result_snapshots` | Insert-only |
| `content_briefs`, `page_audits` | No update once `review_status = 'approved'` |

Enforced in the service layer and covered by `tests/integration/versioning.test.ts`.
